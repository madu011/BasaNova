# BasaNova Android build

## Automated APK

The GitHub Actions workflow **Android APK build** creates an installable, debug-signed Android APK from the current `main` branch.

1. Open the repository on GitHub.
2. Open **Actions**.
3. Select **Android APK build**.
4. Open the latest run and wait until it finishes successfully.
5. In **Artifacts**, download `basanova-android-debug-apk`.
6. Extract the ZIP and install `app-debug.apk` on an Android device.

A debug APK is intended for testing and direct installation. It is not a Play Store production release. A production release needs a protected signing key and release signing configuration; never commit signing keys or passwords to this repository.

## Local build

Requirements: Node.js 22, Java 17, Android SDK and platform/build tools.

```bash
npm install
npm run build:android:debug
```

The generated APK is:

`android/app/build/outputs/apk/debug/app-debug.apk`

The native `android/` directory is generated by Expo Prebuild and is not required to be committed for this managed Expo project.

## What CI verifies before APK assembly

- Clean npm dependency installation (CI generates a lockfile from the current package manifest).
- Expo dependency compatibility.
- Android JavaScript bundle export.
- Native Android project generation.
- Gradle debug APK assembly.
- APK artifact upload.

A successful JavaScript export alone is not an APK build. Treat the APK as ready only when the Android APK workflow completes successfully and the artifact exists. Physical-device installation and feature testing remain separate checks.
