# BasaNova Android build

## Standalone Android APK (recommended)

The GitHub Actions workflow **Android APK build** creates a standalone release-variant APK with the JavaScript bundle packaged inside. This build should start without Metro or a computer running a development server.

1. Open the repository on GitHub.
2. Open **Actions**.
3. Select **Android APK build**.
4. Open the latest run and wait until it finishes successfully.
5. In **Artifacts**, download `basanova-android-release-apk`.
6. Extract the ZIP and install `app-release.apk` on an Android device.

The workflow uses Gradle `assembleRelease`, verifies that the APK exists and is non-empty, and uploads the release artifact. The current CI release variant uses the project's debug signing configuration for direct testing; it is not a Play Store production release. A Play Store release requires a protected production signing key and release signing configuration. Never commit signing keys or passwords.

## Local standalone build

Requirements: Node.js 22, Java 17, Android SDK and platform/build tools.

```bash
npm install
npm run build:android:release
```

The generated APK is:

`android/app/build/outputs/apk/release/app-release.apk`

The native `android/` directory is generated by Expo Prebuild and is not required to be committed for this managed Expo project.

## Development build note

`npm run build:android:debug` creates a debug variant for development. A debug variant may expect Metro and should not be used as the standalone APK distributed for installation. Use the release build above for a self-contained app.

## What CI verifies before APK assembly

- Clean npm dependency installation (CI generates a lockfile from the current package manifest).
- Expo dependency compatibility.
- Android JavaScript bundle export.
- Native Android project generation.
- Gradle release APK assembly.
- Non-empty release APK check.
- Release APK artifact upload.

A successful JavaScript export alone is not an APK build. Treat the APK as ready only when the Android APK workflow completes successfully, the release artifact exists, and the APK has been installed and opened on a physical Android device. Physical-device layout and feature testing remain separate checks.
